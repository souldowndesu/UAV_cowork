# 当前导航与持久化逻辑

当前实验入口默认使用 `safe5`，`safe8` 为 8 m/s 档；`legacy` 留作代码内对照。参数来自 `navigation/config.py` 和 `navigation/profiles.py`。下面描述 safe_route 分支。

## 导航闭环

1. `airsim_io.py` 读取位姿、速度和 LiDAR，缺失 LiDAR 时使用深度图回退；控制接口使用 NED 坐标。
2. `pipeline.py` / `safe_navigation.py` 根据传感器建立随无人机移动的局部占据图，做机身膨胀、距离场和安全判断。局部图中的 FREE / OCCUPIED 会参与当前规划。
3. `persistent_map.py` 保存跨局部窗口的观测；当前地图先从历史已知体素填充，再由新观测校正。地图只持久化 FREE 和 OCCUPIED，没有记录的区域隐式为 UNKNOWN；规划边界 pad 不直接作为观测写入历史。
4. `world_guide.py` 根据历史地图提供较大范围的引导点，支持绕过超出局部规划范围的墙面；局部 A* 仍负责当前感知区域中的接近路线。
5. `astar.py` 搜索局部栅格路线，距离场和未知代价影响路线选择；目标、安全接近点、历史引导与探索策略共同确定当前规划终点。
6. `safe_navigation.py` / `bspline.py` 构建空间曲线并检查沿途净空，对不安全平滑进行回退。路线跟随包含弯道、加速度、jerk 与终点减速限制，碰撞预测、速度安全护栏和过期地图保护进一步限制速度指令。
7. `progress_explorer.py` 在进展不足时产生探索策略，控制已有路线的持续执行与重规划；记录器同步保存状态、地图与预测路线。

`geometry.py`、`occupancy.py`、`distance_field.py`、`raycast.py` 和 `coordinator.py` 提供共同的几何、栅格、感知与控制实现。`navigation/cpp/` 是对应 C++ 加速源码，运行时 `_fast` 位于 navigation 内；源码哈希不匹配时回退 Python 实现。

## 地图如何利用

地图的主要作用是保留已经观察到的墙和空地，让当前局部规划与历史引导不用把所有离开视野的障碍都当成未知。新观测允许修正历史 FREE / OCCUPIED；它不是 SLAM，也没有完整动态障碍置信度或按时间衰减机制。

- `cold`：每轮空图开始，结果中的 `run_map.npz` 记录该轮建图。
- `snapshot`：批次开始时复制初始图，每一轮从同一快照独立复制，上一轮不会训练下一轮。
- `shared`：沿用同一个长期地图并更新；默认 safe5 图路径 `data/maps/persistent_safe.npz`。

局部窗口以外的观测也可持久化供历史引导使用。每轮文件中同时记录初始地图哈希、实际配置、起点和结果，方便区别“算法不同”与“地图先验不同”。录像内持久地图快照用于回放显示；`.npz` 用于重新规划和重飞。

## 目标与验收边界

对于已确认位于建筑内部的目标，允许导航抵达目标附近可达的安全位置，结果为 `safe_approach`，同时保留原目标和安全接近点。确认参数见 PARAMETERS，不能仅因为目标未知就标记其在建筑内部。

24 条示例覆盖六个固定目标、5 / 8 m/s、各自首飞与地图复飞，均通过既定验收并无导航碰撞。移动目标、12 m/s 和任意新场景的稳定性不在这些示例的验证范围内；路线规划也没有保证全局最短路径。目录整理没有修改导航算法、示例数据或验收目标。
