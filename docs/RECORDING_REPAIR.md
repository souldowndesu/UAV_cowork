## 录制格式和失败语义

- 新录制使用 `manifest.json`，`schema_version=2`，事件以 gzip JSON 分块保存。旧 `recording.json` 保持可读。
- manifest 只引用已提交分块，包含分块校验和、事件数、各数据流计数。读取时检查格式版本、路径、重复分块、校验和、事件数、递增序号和数据流计数。
- 地图关键帧和增量都支持障碍移除及空地图。每十个地图快照记录一次关键帧，增量包含新增和删除。
- `complete=true` 表示录制正常结束，不表示导航任务成功。结果事件通过读取器的 `outcomes` 字段保留；部分录制依旧可以读取已提交分块。
- 非有限点云、地图或规划时间戳被忽略，不把无效时间写成零。异步事件入队前复制，调用方后续修改不会污染录制。
- 关闭与入队串行化，避免事件落在结束标记后面。刷新及时报告写入线程错误；重复关闭正常录制或关闭后刷新不会等待已经退出的线程。
- 分块写入成功、manifest 替换失败时，旧 manifest 保留；没有被旧 manifest 引用的分块不算已提交数据。磁盘完全不可写时无法保证额外落盘错误说明，调用方仍会收到异常。
- 独立旧格式保存失败会报错，不能用空数据覆盖旧文件或伪造保存成功。
- 旧入口只调用 `record_*` / `save` 时仍保留完整内存历史，不会截断为最后 512 帧。需要有界实时缓冲时，必须在第一条事件前调用 `start(path)`，并在结束时 `close()`；全量历史由写盘线程保存，内存每个数据流只保留最后 512 条。已有历史后尝试 `start` 会明确报错，避免静默丢失数据。

## 回放行为

```powershell
python replay.py --results-dir results --serve
```

入口保持 `replay.py`，`--serve` 不依赖 stdin。无需启动仿真器即可查看已有录制。

列表使用稳定 ID 并保留刷新前的选择；纯数字的 16 位 ID 也按 ID 处理。损坏的元信息以失败条目展示，不影响其余录制。读取失败返回 HTTP 422 及 JSON 错误，页面显示原因。

晚返回的录制请求不能覆盖更新的选择；切换实时模式后，旧回放响应不会重新切回回放。实时模式清除上一段录制的历史地图，按序号去重，同时保留有效的空地图更新。离线显示按时间排序，未完整结束的录制有明确标注。最终历史总览默认关闭，避免混入未来地图。
